      How it works

      Six agents, each with one job

      Several independent readers vote on each field. Deterministic checks decide what counts as verified, and everything else goes to the pharmacist.

      Intake

      Checks image quality: blur, skew, resolution, missing pages. A bad scan is flagged at the door, before anything is read.

      imagesmulti-page PDFfax webhook

      Extraction

      Two separate OCR models read the page with layout boxes. GLiNER2 tags the order fields, and an open Qwen chat model fills a strict JSON schema.

      LightOnOCRGLM-OCRGLiNER2Qwen

      Consensus

      Votes field by field across the model passes. When readers disagree, the disagreement becomes a reason a pharmacist can see. It is never settled by silently picking one.

      per-field voting

      Verification

      Looks up drugs in RxNorm and ranks the matches with Qwen3-Reranker. Checks the prescriber in NPPES and runs NPI/DEA checksums, the sig parser, LASA (look-alike/sound-alike) drug rules and dose ranges.

      RxNormNPPESLuhn / DEAISMP

      Triage

      Turns confidence and flags into a queue status: Blocked, Needs review, or Ready to approve. The pharmacist always sees the worst problem first.

      queuepharmacy memory

      Order

      Once a pharmacist approves, the order exports as JSON, CSV, or an HL7 FHIR R4 MedicationRequest, with a full trace of how each field was read.

      FHIR R4audit trail

      The safety invariant

      Models can only add doubt. They can never take it away.

      New models and pharmacy memory can only add candidates, add reasons, rank options or raise flags. Only deterministic checks backed by agreement between readers, or a pharmacist, can mark a field verified.

      Verified

      Independent readers agree and every deterministic check passes.

      Needs review

      The value is plausible but something is uncertain. Candidates and reasons are attached.

      Unreadable

      The value is withheld. PillSpark won't show its best guess, because a pharmacist might anchor on it.

      Missing

      The prescription doesn't contain it. Checks that depend on it are paused, not skipped.

      # One choke point for every status change (simplified)
def set_status(field, status, source):
    if status == "verified" and source not in TRUSTED:
        raise UnsafeVerification(
            f"{source} may add doubt, never verify")
    audit.append(field, status, source)
    field.status = status

TRUSTED = {"deterministic_checks", "pharmacist"}
# not trusted: "sie_model", "memory", "reranker"
      Blocks on illegible tokens, LASA drugs with readings that disagree, doses outside the expected range, and ISMP error-prone abbreviations such as q.d.
      Blocks when an NPI or DEA checksum fails or the prescriber can't be found in NPPES.
      If SIE goes down, every field falls back to "needs review". PillSpark never falls back to guessing.

      Open models on Superlinked SIE

      Everyday jobs moved off frontier models

      Each job runs on an open model served by Superlinked SIE. Every model is named on one line of models.yaml, so swapping one is a one-line change. To keep real PHI off third-party servers, point SIE_BASE_URL at a self-hosted SIE.

      Pharmacy memory with cognee

      Agents learn from every pharmacist fix

      When a pharmacist resolves a flag, the correction goes into shared memory. The next time a fax arrives from that prescriber, memory can add a "Seen before" candidate that links to the original correction. Memory can never verify a field.

      pharmacist_corrections

      The field, each model's raw reading, the final value, the reason, the prescriber's NPI and a timestamp.

      write: pharmacistread: all agents
      prescriber_patterns

      Patterns at the prescriber level, such as "this prescriber's handwritten g often reads as q" or "usually prescribes metformin 500 mg tablets".

      write: verification-agentread: all
      agent_notes

      Each agent's own failure notes, for example "OCR pass 2 misreads strengths that have a trailing zero".

      write: each agentread: all
      No patient identifiers ever reach memory. Before any write, text goes through SIE's PII redaction model and patient fields are stripped structurally. Memory is keyed on prescriber, drug and field patterns only. When a pharmacist accepts or rejects a suggestion, that feedback goes back to cognee, so useful patterns get stronger and wrong ones fade.

      Built to use on Monday

      The parts a pharmacy needs, not just a model

      Roles & sign-in

      Pharmacist, technician and admin roles. Only a pharmacist can resolve a flag or approve an order.

      Live queue

      Status chips, flag counts, the age of each order, filters and search. New faxes show up without a refresh.

      Append-only audit

      Every field change, resolution, approval and export is recorded with the user, the time, and the value before and after.

      FHIR export

      Approved orders export as JSON, as CSV, or as an HL7 FHIR R4 MedicationRequest that is validated against the R4 shape.

      Fax webhook

      Accepts drag-and-drop uploads, multi-page PDFs, and a signed webhook a fax provider can call. Every intake carries an idempotency key.

      Background jobs

      A worker processes each order. Calls to SIE and the drug and prescriber registries retry with backoff and time out, and a stuck order shows as failed.

      PHI-safe logs

      Structured logs pass through a PHI scrubber and carry request IDs. No image bytes in traces, and no PHI in error messages.

      One-click deploy

      A Docker image plus a Render Blueprint with Postgres, a persistent disk, and the /healthz and /readyz health checks.
